API & Jobs

— inter-couche : chaque endpoint appelle un orchestrateur, jamais un DAO directement
POST/auth/login, /register
→ appelle UserService (+ core/security.py pour hash & JWT)
POST / GET/abstracts
→ appelle AbstractService
PATCH/duplicates/{id}
→ appelle AbstractService (review humaine, via DuplicateFlagDAO)
POST / PATCH/editions
→ appelle EditionService
GET/editions/{id}/clusters
→ appelle DashboardService
GET/editions/{id}/dashboard
→ appelle DashboardService
schedulerClusteringJob
→ appelle ClusteringService + ClusterDAO + AuditLogService, 1h après clôture
api/deps.py — get_db() : une session SQLAlchemy par requête HTTP. Les DAO ne font que add()/flush(), jamais commit() ; c'est get_db() qui commite si la requête entière réussit et fait rollback() sinon — pour que la chaîne endpoint → orchestrateur → plusieurs DAO reste une seule transaction atomique.

Inversion de dépendance : les services (couche 3) ne référencent que des noms d'interfaces (couche 2, teal), jamais MySQLAbstractDAO ou Specter2Provider directement — changer de base ou de modèle d'embedding se fait en couche 2 uniquement.

Statut du code : seul MySQLAbstractDAO a une implémentation réelle à ce stade ; les autres cases ambrées sont des fichiers stub (commentaire seul), à écrire sur ce même patron.
